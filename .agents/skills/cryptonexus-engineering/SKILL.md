# cryptonexus-engineering

## Purpose
Control the development workflow.

## Enforced Workflow
RECON → READ RELEVANT SPEC → PLAN → IMPLEMENT → TEST → AUDIT → REPORT → STOP

## Rules
- Never implement future phases.
- Never claim a test ran unless it actually ran.
- Never claim functionality is complete without verification.
- Never silently change architecture.
- Prefer the smallest correct change.
- Reuse existing code where appropriate.
- Stop after the authorized component.

## Component Report Format
Include:
FILES CREATED, FILES MODIFIED, TECHNOLOGIES USED, ALGORITHMS USED, COMMANDS/TESTS RUN, ACTUAL RESULTS, REQUIREMENT TRACEABILITY, RISKS/BLOCKERS, DOCUMENTATION CHANGES, STATUS.
